# Test Completion Report Template — ISO/IEC/IEEE 29119-3, 7.4 (Annex G)

One report per release, written when the release is being cut. It goes to
`docs/test-reports/{release}-test-completion-report.md`, where `{release}` is the tag or version the
report covers (`v1.2.0`).

The section names below are the ones this template carries. **Test measures** and **Residual risks**
are the two sections this template treats as the ones a certification auditor would sample first —
write them with the run's actual numbers and the things that were not verified, not with
reassurances.

## Provenance of these sections

The section set corresponds to Clause 7.4 of ISO/IEC/IEEE 29119-3:2021 (Annex G), and the section
names are as this template carries them — this template's own set, not a reproduction of the
standard's. **The standard's internal detail for each section is not reproduced here** — over and
above its name, what the standard requires of each section has not been copied into this
repository. The prompts in the block above say what *this* repository can fill into each section,
from the artifacts it actually produces (`.trx`, the traceability validator, incident reports).

- **Test measures** deliberately does not define a metric. Quality characteristics come from
  `.ai/reference/quality-model.md`, and its boundary — 25010 defines no metric; measurement is
  ISO/IEC 25023, evaluation is ISO/IEC 25040 — is why this section quotes tools rather than
  inventing measures.
- **Residual risks** is the reason this report is adopted at all: it is the section that records
  what the release does *not* verify.
- No certification or conformity claim is made by this report or from it. See
  `.ai/reference/test-documentation.md`.

## Usage

1. Write one report per release to `docs/test-reports/{release}-test-completion-report.md`. Create
   the directory on first use.
2. Fill sections 2 and 6 from the run — never from memory. Quote the `.trx` counts and the
   `validate-traceability.py` output.
3. A section with nothing to report gets a line saying so ("None." or "None identified — the run
   covered every criterion in scope"), not a deleted heading: a missing section is indistinguishable
   from an unread one.
4. Record residual risks even when the release proceeds. A release with an empty risk section and a
   green run is rare enough that writing one should prompt a second look.
5. This report is release-scoped. The per-slice test plan is not repeated here — link it from
   section 8.
